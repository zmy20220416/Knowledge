# Organize Knowledge

负责维护 Knowledge 的长期结构。

## 工作流程

1. 查看当前 Git 状态。
2. 检查 inbox/。
3. 搜索重复或高度相关的笔记。
4. 判断哪些内容应该移动到正式分类。
5. 判断哪些笔记可以合并。
6. 检查明显过时的内容。
7. 补充必要的相关知识链接。
8. 检查修改结果。
9. 输出修改摘要。

## 重要原则

不要直接删除知识。

如果发现重复：

1. 找出主要笔记。
2. 合并有价值的信息。
3. 保留来源和上下文。
4. 确认内容没有丢失。
5. 只有明确安全时才删除重复文件。

## inbox

inbox 是临时区域。

整理 inbox 时：

- 可以移动到正式分类。
- 可以合并已有笔记。
- 可以保留暂时无法分类的内容。
- 不要因为内容暂时没有价值就自动删除。

## 过时知识

发现可能过时的信息时：

不要直接删除。

可以标记：

> 注意：该内容可能已经过时，需要重新验证。

## Git

整理过程中不要自动 commit。

完成后执行：

git status
git diff

检查修改内容。

## 输出

完成后告诉用户：

- 新增了什么
- 修改了什么
- 移动了什么
- 合并了什么
- 哪些内容可能过时
- 哪些内容需要人工确认
